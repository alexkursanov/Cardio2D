# Входные файлы: конфигурация, протоколы, серии, очередь

Все входные файлы — текст (JSON или список строк). Прогон полностью
определяется **файлом конфигурации**. Серия — это конфигурация плюс
список изменяемых параметров. Очередь — список конфигураций и серий.

| Файл | Формат | Чем проверить без счёта |
|------|--------|-------------------------|
| конфигурация прогона | JSON, [раздел 1](#1-конфигурация-прогона) | `python -m cardiac_em show CFG.json` |
| серия | JSON, [раздел 10](#10-серия) | `python -m cardiac_em sweep SWEEP.json --dry-run` |
| очередь | текст, [раздел 11](#11-очередь) | `python scripts/queue.py Q.txt --dry-run` |

Единицы везде: **мм, мс, кПа**; диффузия — мм²/мс, скорость — мм/мс
(численно равно м/с); концентрации — мМ; потенциал TNNPM — мВ.

Готовые примеры лежат в `examples/`:

| Файл | Что это |
|------|---------|
| `tnnpm_ischemia.json` | TNNPM, 6×6 мм, круговая ишемия «15 мин», один стимул, 400 мс |
| `tnnpm_night.json` | 8×8 мм, h = 0.05 мм, 4 удара по 500 мс |
| `tnnpm_1hz.json` | то же, 10 ударов с частотой 1 Гц |
| `sweep_tnnpm_night.json`, `sweep_tnnpm_1hz.json` | серии: три стадии ишемии (режим zip) |
| `ischemia_base.json`, `regions_ischemia.json`, `sweep_tmax.json` | модель Роджерса–МакКаллоха (исходная упрощённая) |
| `queue_example.txt` | образец файла очереди |

Пустую конфигурацию со значениями по умолчанию создаёт
`python -m cardiac_em init configs/new.json --nx 80 --coarsening 4`.

## 1. Конфигурация прогона

Верхний уровень JSON:

```json
{
  "cell_model": "tnnpm",
  "passive_material": "transversely_isotropic_exponential",
  "mesh":        { … },   // сетки — раздел 2
  "tissue_base": { … },   // свойства ткани — раздел 3
  "cell_params": { … },   // параметры клетки для всей ткани — раздел 4
  "regions":     [ … ],   // неоднородности — раздел 5
  "stimulus":    { … },   // протокол стимуляции — раздел 6
  "time":        { … },   // шаги и длительность — раздел 7
  "preload":     { … },   // преднагрузка — раздел 7
  "output":      { … },   // что писать — раздел 9
  "restart":     { … }    // продолжение — раздел 8
}
```

Любое поле можно не указывать — возьмётся значение по умолчанию.
Любое поле можно поменять из командной строки: `--set путь=значение`,
где путь — ключи через точку, номер элемента списка — число:
`--set regions.0.params.r=1.5`. Значение — в синтаксисе JSON
(`[1,1001]`, `true`, `0.5`); строку можно без кавычек.

### Модель клетки — `cell_model`

| Значение | Что это | Переменных | Потенциал |
|----------|---------|-----------|-----------|
| `"tnnpm"` | **основная**: TNNP + механика саркомера, в клетке только сократительный элемент; пассивная сила — в ткани; клетка получает от ткани длину и скорость волокна | 26 | мВ |
| `"tnnpm_isometric"` | полная реологическая схема исходной TNNPM (изометрия), без обратной связи от ткани | 29 | мВ |
| `"rogers_mcculloch"` | упрощённая двухпеременная модель (исходная версия кода) | 2 | безразм. 0…1 |

### Пассивный материал — `passive_material`

Сейчас один: `"transversely_isotropic_exponential"` (параметры — в
`tissue_base.passive`, раздел 3).

## 2. Сетки — `mesh`

Две прямоугольные сетки одной области: **электрическая** (мелкая, для
фронта возбуждения) и **механическая** (грубее).

```json
"mesh": {
  "electric":   {"kind": "rectangle", "nx": 160, "ny": 160, "lx_mm": 8.0, "ly_mm": 8.0, "cell_type": "quadrilateral"},
  "mechanical": {"kind": "rectangle", "nx": 40,  "ny": 40,  "lx_mm": 8.0, "ly_mm": 8.0, "cell_type": "quadrilateral"}
}
```

| Поле | Смысл |
|------|-------|
| `nx`, `ny` | число ячеек по x и y (узлов на 1 больше) |
| `lx_mm`, `ly_mm` | размер области, мм (у обеих сеток одинаковый) |
| `cell_type` | `"quadrilateral"` (рекомендуется) или `"triangle"` |

Рекомендации:

* шаг электрической сетки h = lx/nx: для TNNPM **≤ 0.1 мм** (0.05 мм —
  аккуратно, 0.1 — для быстрых проб);
* **вложенность**: пусть `nx_эл` делится на `nx_мех` (160/40 = 4) —
  тогда активное напряжение переносится между сетками точно (`show`
  пишет «вложенные … точный перенос»);
* в механической сетке не меньше ~10 ячеек по стороне (при 1 ячейке
  зажатые края не дают ткани деформироваться — `show` предупредит).

## 3. Свойства ткани — `tissue_base`

```json
"tissue_base": {
  "reaction":   {"c1": 0.26, "c2": 0.1, "a": 0.13, "b": 0.013, "d": 1.0},
  "conduction": {"d_long": 0.15, "d_trans": 0.05, "fiber_angle_deg": 0.0},
  "active":     {"t_max": 60.0},
  "passive":    {"mu": 1.0, "b_iso": 1.0, "mu_f": 3.0, "b_f": 2.0, "kappa": 100.0}
}
```

| Группа.поле | Ключ в регионе | Единицы | Смысл |
|-------------|----------------|---------|-------|
| `reaction.c1 … d` | `AP_c1 … AP_d` | — | параметры модели Роджерса–МакКаллоха; **для TNNPM не используются** |
| `conduction.d_long` | `D_LONG` | мм²/мс | диффузия вдоль волокна (скорость проведения ∝ √D) |
| `conduction.d_trans` | `D_TRANS` | мм²/мс | диффузия поперёк волокна |
| `conduction.fiber_angle_deg` | `FIBER_ANGLE_DEG` | градусы | направление волокна от оси x |
| `active.t_max` | `T_MAX` | кПа | пиковое изометрическое активное напряжение здоровой ткани (для TNNPM; у Роджерса–МакКаллоха пик — T_MAX/4) |
| `passive.mu` | `MU` | кПа | изотропная жёсткость матрицы |
| `passive.b_iso` | `B_ISO` | — | нелинейность матрицы |
| `passive.mu_f` | `MU_F` | кПа | жёсткость вдоль волокна |
| `passive.b_f` | `B_F` | — | нелинейность вдоль волокна |
| `passive.kappa` | `KAPPA` | кПа | штраф сжимаемости (больше — ближе к несжимаемости) |

Во втором столбце — имена, под которыми параметр переопределяется в
регионе (раздел 5).

## 4. Параметры клетки для всей ткани — `cell_params`

Для TNNPM — словарь «имя → значение», меняющий параметр модели во
**всей** ткани:

```json
"cell_params": {"K_o": 6.2}
```

Допустимые имена и значения по умолчанию (TNNPM):

| Имя | По умолч. | Единицы | Смысл |
|-----|-----------|---------|-------|
| `K_o` | 5.4 | мМ | внеклеточный K⁺ (ишемия: ↑) |
| `Na_o` | 140 | мМ | внеклеточный Na⁺ |
| `Ca_o` | 2.0 | мМ | внеклеточный Ca²⁺ |
| `ATP_i` | 6.8 | мМ | внутриклеточный АТФ (ишемия: ↓) |
| `KmATP` | 0.0976 | мМ | полунасыщение K(ATP)-канала по АТФ (ишемия: ↑) |
| `g_KATP` | 1.593 | нС/пФ | максимальная проводимость I_K(ATP) |
| `g_Na`, `g_CaL`, `g_K1`, `g_Kr`, `g_Ks`, `g_to`, `g_pK`, `g_bna`, `g_bCa`, `g_pCa` | 14.838, 5e-5, 5.405, 0.153, 0.392, 0.735, 0.0146, 2.9e-4, 5.92e-4, 0.2476 | — | проводимости ионных токов |
| `K_NaCa`, `P_NaK`, `K_mNa` | 1e4, 2.724, 40 | — | обменник Na/Ca, насос Na/K |
| `Vmax_up`, `V_rel`, `V_leak` | 0.00765, 0.1224, 3.6e-4 | мМ/мс | захват, выброс, утечка Ca²⁺ в СР |

Неизвестное имя — ошибка при `show`.

## 5. Регионы (неоднородности) — `regions`

Список областей, в которых параметры отличаются от базовой ткани:

```json
"regions": [
  {
    "shape": "circle",
    "name": "ишемия",
    "params": {"cx": 5.0, "cy": 4.0, "r": 2.0},
    "overrides": {"cell:K_o": 9.4, "cell:ATP_i": 4.0, "cell:KmATP": 0.38, "T_MAX": 40.0}
  },
  {
    "shape": "rect",
    "name": "рубец",
    "params": {"x0": 1.0, "x1": 2.0, "y0": 0.0, "y1": 8.0},
    "overrides": {"D_LONG": 0.01, "D_TRANS": 0.005, "MU_F": 30.0}
  }
]
```

| Форма | `params` |
|-------|----------|
| `"circle"` | `cx`, `cy` — центр, `r` — радиус, мм |
| `"rect"` | `x0`, `x1`, `y0`, `y1` — границы, мм |

`overrides` — что меняется внутри:

* ключи ткани из таблицы раздела 3: `D_LONG`, `D_TRANS`,
  `FIBER_ANGLE_DEG`, `T_MAX`, `MU`, `B_ISO`, `MU_F`, `B_F`, `KAPPA`
  (и `AP_*` для Роджерса–МакКаллоха);
* параметры клетки — с префиксом **`cell:`** и именем из раздела 4:
  `cell:K_o`, `cell:ATP_i`, `cell:g_Na`, …

Правила:

* регионы применяются **по порядку списка**: где области
  перекрываются, действует более поздняя;
* 0 в картах регионов — базовая ткань, 1 — `regions[0]`, 2 —
  `regions[1]` и т.д. (так же в файлах результатов);
* электротоническая длина на плато ≈ √(D/g_m) ≈ 2 мм: регион заметно
  меньше неё здоровая ткань «подтягивает» к себе — эффект ослабнет.

### Ишемия: стадии

Параметры автора модели для регионов ишемии (`cell:…`):

| Стадия | `K_o`, мМ | `ATP_i`, мМ | `KmATP`, мМ | APD одиночной клетки, мс |
|--------|----------|------------|------------|--------------------------|
| норма | 5.4 | 6.8 | 0.09 | 255 |
| 5 мин | 6.2 | 6.0 | 0.30 | 236 |
| 10 мин | 8.0 | 4.5 | 0.35 | 207 |
| 15 мин | 9.4 | 4.0 | 0.38 | 188 |

Для ишемии обязательно задайте `preload.cell_relax_ms` ≥ 300 (раздел 7):
иначе ткань не успеет прийти к ишемическому покою до первого стимула.

## 6. Протокол стимуляции — `stimulus`

Стимул подаётся в полосу у левого края (x = 0): амплитуда спадает по
экспоненте вглубь и обрезается при x > `x_max_mm`. Каждый импульс —
трапеция во времени.

```json
"stimulus": {
  "times_ms": [1.0, 1001.0, 2001.0],
  "duration_ms": 2.0,
  "amplitude": 100.0,
  "rise_time_ms": 0.1,
  "decay_length_mm": 0.5,
  "x_max_mm": 1.0
}
```

| Поле | Единицы | Смысл |
|------|---------|-------|
| `times_ms` | мс | моменты **начала** импульсов, по возрастанию, абсолютное время |
| `duration_ms` | мс | длительность импульса |
| `amplitude` | TNNPM: пА/пФ (= мВ/мс); РМ: безразм. | сила стимула. Для TNNPM 100 при 2 мс надёжно возбуждает |
| `rise_time_ms` | мс | длительность фронтов трапеции (2·rise ≤ duration) |
| `decay_length_mm` | мм | характерная длина спада вглубь |
| `x_max_mm` | мм | дальше этого x стимула нет; должно быть ≥ 2 ячеек эл. сетки |

Импульсы не должны перекрываться (иначе ошибка).

### Типовые протоколы

**Ритм S1 с периодом BCL** (N ударов, первый на 1 мс):
`times_ms = [1, 1+BCL, 1+2·BCL, …]`, `t_end_ms = N·BCL`.

| Частота | BCL | 10 ударов: `times_ms` |
|---------|-----|-----------------------|
| 1 Гц | 1000 | `[1, 1001, 2001, …, 9001]`, `t_end_ms = 10000` |
| 2 Гц | 500 | `[1, 501, …, 4501]`, `t_end_ms = 5000` |

Список удобно сгенерировать в Python:
`[1 + k*1000 for k in range(10)]`.

**S1–S2 (реституция, уязвимое окно):** серия S1 для установления ритма,
затем внеочередной S2 через интервал сцепления CI после последнего S1:
`times_ms = [1, 1001, …, 9001, 9001 + CI]`. Для кривой реституции —
серия по CI (раздел 10, значения параметра — целые списки).

**Экономия времени:** установите ритм один раз, сохраните состояние и
запускайте разные S2 **продолжением** от него (раздел 8).

**Направление волокна** относительно фронта: `fiber_angle_deg` (0 —
волокно вдоль x, по ходу фронта; 90 — поперёк).

## 7. Время и преднагрузка — `time`, `preload`

```json
"time":    {"dt_electric_ms": 0.05, "n_electric_per_mech": 20, "t_end_ms": 10000.0},
"preload": {"stretch": 1.2575, "n_steps": 10, "cell_relax_ms": 300.0}
```

| Поле | Смысл |
|------|-------|
| `time.dt_electric_ms` | шаг электрики, мс. В примерах 0.05; модель рекомендует 0.02 — для итоговых результатов проверьте, что уменьшение шага вдвое не меняет CV и APD |
| `time.n_electric_per_mech` | механика решается раз в столько электрических шагов (20 × 0.05 = 1 мс) |
| `time.t_end_ms` | конец счёта, **абсолютное** время, мс |
| `preload.stretch` | растяжение вдоль волокна λ_f перед зажимом краёв (1.2575 ↔ длина саркомера 2.64 мкм при 2.1 мкм в покое); 1 — без преднагрузки |
| `preload.n_steps` | за сколько шагов растягивать (больше — надёжнее сходимость) |
| `preload.cell_relax_ms` | счёт электрики без стимула **до** растяжения, мс; нужен для регионов с другим покоем (ишемия) — ≥ 300 |

Порядок этапов: подготовка клеток → растяжение → зажим всех краёв в
растянутом положении → счёт от t = 0 со стимулами.

## 8. Продолжение — `restart`

```json
"restart": {"checkpoint_path": "runs/a/ckpt_last.npz", "reset_time": false, "allow_interp": false}
```

или флагами `--restart`, `--reset-time`, `--allow-interp`.

| Поле | Смысл |
|------|-------|
| `checkpoint_path` | чекпоинт, откуда взять состояние (`null` — обычный старт) |
| `reset_time` | начать отсчёт времени с нуля (удобно для «нового эксперимента из готового состояния») |
| `allow_interp` | разрешить продолжение на **другой** сетке (перенос по ближайшему узлу) |

При продолжении преднагрузка и подготовка клеток не выполняются —
состояние (клетки и перемещения) берётся из чекпоинта. Остальную
конфигурацию (стимулы, регионы, вывод) можно менять.

Какие чекпоинты есть — в [OUTPUT_FILES.md](OUTPUT_FILES.md#чекпоинты).
Типовые сценарии:

```bash
# удлинить прогон a (он закончился на 3000 мс) до 5000 мс
python -m cardiac_em run CFG.json --out runs/a2 --restart runs/a/ckpt_last.npz \
    --t-end 5000 --set "stimulus.times_ms=[3001,4001]"

# S2 с разными интервалами из установившегося ритма (прогон rhythm закончен на 9500 мс,
# последний S1 — на 9001): время продолжается, S2 — в абсолютном времени
python -m cardiac_em run CFG.json --out runs/s2_300 --restart runs/rhythm/ckpt_last.npz \
    --t-end 10000 --set "stimulus.times_ms=[9301]"

# новый протокол из готового преднагруженного состояния, время с нуля
python -m cardiac_em run CFG.json --out runs/b --restart runs/a/ckpt_preloaded.npz \
    --reset-time --t-end 3000 --set "stimulus.times_ms=[1,301,601]"
```

## 9. Вывод — `output`

```json
"output": {
  "out_dir": "runs/my_run",
  "save_every_mech_steps": 50,
  "snapshot_times_ms": [5, 50, 150, 300, 9005, 9050, 9150, 9300],
  "ckpt_every_mech_steps": 250,
  "ckpt_keep_all": false,
  "write_region_maps": true,
  "record_activation": true,
  "apd_level": 0.9
}
```

| Поле | Смысл |
|------|-------|
| `out_dir` | папка прогона (флаг `--out`) |
| `save_every_mech_steps` | запись полей в XDMF для ParaView каждые N мех. шагов (N мс при шаге 1 мс). Главный потребитель диска: 20 → ~2.5 ГБ на 10 с сетки 161², 50 → ~1 ГБ |
| `snapshot_times_ms` | моменты снимков `.npz` для анализа (ноутбуки 03–05). **Первый снимок ставьте рано** (≤ 5 мс) — он служит кадром «после преднагрузки» |
| `ckpt_every_mech_steps` | как часто обновлять `ckpt_last.npz` |
| `ckpt_keep_all` | хранить все чекпоинты (`ckpt_t….npz`), а не только последний |
| `write_region_maps` | записать карты регионов (`regions_*.xdmf`) |
| `record_activation` | вести карты активации и APD (`activation.npz`) |
| `apd_level` | уровень реполяризации для APD: 0.9 → APD90 |

Что появляется в папке прогона — [OUTPUT_FILES.md](OUTPUT_FILES.md).

## 10. Серия

Файл серии, например `configs/my_sweep.json` (лежит рядом с `configs/my_first.json`):

```json
{
  "base": "my_first.json",
  "out_root": "runs/my_sweep",
  "mode": "grid",
  "parameters": {
    "regions.0.params.r": [1.0, 1.5, 2.0],
    "regions.0.overrides.cell:K_o": [5.4, 9.4]
  },
  "stop_on_error": false
}
```

| Поле | Смысл |
|------|-------|
| `base` | конфигурация: путь **относительно файла серии** или сам словарь конфигурации |
| `out_root` | папка серии — путь от папки, **из которой запускают** (всегда запускайте из корня проекта `~/cardio2d`); точки — `run_000`, `run_001`, … |
| `mode` | `"grid"` — все сочетания (здесь 3×2 = 6); `"zip"` — i-е значения вместе (списки одной длины) |
| `parameters` | путь параметра → список значений; пути — как у `--set` |
| `stop_on_error` | прервать серию при первой ошибке (для `cardiac_em sweep`) |

Значением может быть и **список** — тогда в `parameters` список списков.
Пример — реституция S1–S2 по интервалу сцепления:

```json
"parameters": {
  "stimulus.times_ms": [[1, 1001, 2001, 2251], [1, 1001, 2001, 2301], [1, 1001, 2001, 2401]]
}
```

Все точки проверяются **до** начала счёта — опечатка в последней точке
обнаружится сразу (`--dry-run`).

Запуск: через очередь (раздел 11) — точки считаются параллельно; или
`python -m cardiac_em sweep SWEEP.json` (под `mpirun -n N` — точки по
очереди, каждая на N ядрах). Повторный запуск пропускает готовые точки.

## 11. Очередь

Текстовый файл для `scripts/queue.py`, по заданию в строке:

```text
# комментарий
configs/sweep_stages.json                                   # серия
configs/my_first.json --out runs/long --t-end 3000          # один прогон + флаги run
configs/my_first.json --out runs/b --restart runs/long/ckpt_last.npz --t-end 5000
```

* пути — от корня проекта (очередь сама работает из корня, откуда бы её ни запустили);
* у одиночного прогона допустимы флаги `cardiac_em run`: `--out`,
  `--t-end`, `--set`, `--restart`, `--reset-time`, `--allow-interp`;
* у серии флагов нет — всё в её JSON;
* задания выполняются сверху вниз; задание-продолжение ставьте
  **после** того, от которого оно продолжается, и запускайте очередь с
  `--parallel 1` или отдельной очередью после первой — очередь не
  знает о зависимостях между строками;
* строку с ошибкой (нет файла, опечатка в `--set`) очередь пропускает
  и пишет об этом в свой лог.

Параметры запуска очереди — `python scripts/queue.py -h` и
[STUDENT_GUIDE.md, шаг 8](STUDENT_GUIDE.md#9-шаг-8--очередь-расчётов-основной-способ-запуска).
