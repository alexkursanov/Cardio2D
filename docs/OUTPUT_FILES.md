# Выходные файлы: что лежит в папке прогона и серии

Каждый прогон пишет всё в свою папку (`output.out_dir`, флаг `--out`).
Анализ (ноутбуки 03–05, модуль `cardiac_em.analysis`) читает **только
эти файлы** — DOLFINx для него не нужен, папку можно скопировать на
свой компьютер.

## Папка прогона

```
runs/my_run/
├── run.json                 паспорт прогона: статус, конфигурация, версии, предупреждения
├── series.csv               ряд диагностики на каждом механическом шаге
├── preload.csv              ряд диагностики на шагах преднагрузки
├── activation.npz           карты активации, реполяризации, APD по ударам
├── snapshots/
│   ├── snap_t00000005.000ms.npz   снимок всех полей в заказанный момент
│   └── …
├── electrics.xdmf + .h5     поля электрики во времени (для ParaView)
├── mechanics.xdmf + .h5     поля механики во времени (для ParaView)
├── regions_electric.xdmf + .h5, regions_mechanical.xdmf + .h5   карты регионов
├── ckpt_preloaded.npz       состояние сразу после преднагрузки
├── ckpt_last.npz            последнее сохранённое состояние
├── analysis/                ← пишет ноутбук 03 (CSV, JSON)
└── figures/                 ← пишут ноутбуки 04 и 05 (PNG, GIF)
runs/my_run.log              ← вывод счёта, если запускали через очередь или nohup
```

Что можно удалять, когда анализ сделан: `*.h5` + `*.xdmf` (самое
большое), `ckpt_*.npz` (нужны только для продолжения). **Не удаляйте**
`run.json`, `series.csv`, `activation.npz`, `snapshots/` — это и есть
результат.

---

## run.json — паспорт прогона

JSON. Пишется в начале, обновляется во время счёта, дописывается в
конце. Главные поля:

| Поле | Смысл |
|------|-------|
| `status` | `running` — считается (или процесс убит); `finished` — успешно; `failed` — ошибка |
| `progress.t_ms` | до какого времени досчитано (обновляется во время счёта) |
| `started`, `finished`, `elapsed_s` | время начала/конца (UTC) и длительность, с |
| `error` | текст ошибки при `failed` (с моментом `t`, на котором упало) |
| `config` | **полная конфигурация** прогона — по ней прогон можно повторить |
| `models` | модель клетки и имена её переменных (`cell_states`), материал, способ переноса T_act |
| `meshes` | параметры и размеры обеих сеток |
| `schedule` | `t_start_ms`, `t_end_ms`, число шагов |
| `restart` | откуда взято начальное состояние (при продолжении) |
| `warnings` | предупреждения конфигурации и счёта |
| `environment` | версии Python, numpy, DOLFINx, PETSc; число рангов MPI; сервер; git-коммит кода |
| `outputs` | список файлов прогона |

Быстро посмотреть: `python -m cardiac_em status runs/my_run`.
Повторить прогон точно: достать `config` в файл
(`python -c "import json;print(json.dumps(json.load(open('runs/my_run/run.json'))['config'],indent=2,ensure_ascii=False))" > configs/repeat.json`).

## series.csv — временной ряд

CSV с заголовком, строка на каждый механический шаг (обычно 1 мс) и
начальная строка. Читается `pandas.read_csv`, Excel, `numpy.genfromtxt`.
Во время счёта файл дописывается — за ходом можно следить `tail -f`.

| Столбец | Единицы | Смысл |
|---------|---------|-------|
| `t_ms` | мс | время |
| `mech_index` | — | номер механического шага (пусто в начальной строке) |
| `u_min`, `u_max` | мВ (TNNPM) | минимум и максимум трансмембранного потенциала по ткани |
| `t_act_electric_max` | кПа | максимум активного напряжения, **переданного клетками**, на электрической сетке |
| `t_act_electric_integral` | кПа·мм² | его интеграл по области |
| `t_act_mech_max`, `t_act_mech_integral` | кПа, кПа·мм² | то же после переноса на механическую сетку (интегралы должны совпадать с электрическими — контроль переноса) |
| `t_act_actual_max`, `t_act_actual_integral` | кПа, кПа·мм² | **действующее** активное напряжение — с учётом закона сила–скорость (при укорочении меньше переданного) |
| `lambda_f_min`, `lambda_f_max` | — | наименьшее и наибольшее растяжение волокна λ_f по ткани (относительно исходной, нерастянутой геометрии) |
| `J_min`, `J_max` | — | det F — изменение объёма (≈ 1 при почти несжимаемом материале) |
| `sigma_xx_min`, `sigma_xx_max` | кПа | напряжение Коши σ_xx (вдоль x) |
| `newton_iterations` | — | итераций Ньютона на шаге механики (обычно 2–4; рост — признак трудностей) |

`preload.csv` — те же механические столбцы на каждом шаге преднагрузки
(`step`, `lambda_f_*`, `J_*`, `sigma_xx_*`, `newton_iterations`).

## activation.npz — карты активации и APD

numpy-архив (`np.load`), значения по **узлам электрической сетки**,
упорядочены по (y, x): `act[:, k].reshape(ny+1, nx+1)` — карта удара k.

| Ключ | Форма | Смысл |
|------|-------|-------|
| `coords` | (N, 2) | координаты узлов, мм |
| `region` | (N,) | номер региона узла: 0 — базовая ткань, i — `regions[i-1]` |
| `act` | (N, B) | время активации в каждом из B ударов, мс (NaN — не возбудился) |
| `repol` | (N, B) | время реполяризации, мс |
| `peak` | (N, B) | пик потенциала в ударе |
| `threshold` | — | порог активации (TNNPM: −40 мВ) |
| `apd_level` | — | уровень APD (0.9 → APD90) |
| `v_rest`, `t_start_ms`, `t_end_ms`, `dt_ms` | — | как считалось |

Определения:

* **активация** — пересечение порога снизу вверх, момент уточнён
  линейной интерполяцией между шагами (точность — доли шага);
* **реполяризация** — спад до V_base + (1 − apd_level)·(V_peak − V_base),
  где V_peak — пик этого удара в узле, V_base — минимум в диастоле перед
  ним в этом же узле (в ишемии покой деполяризован, поэтому уровень берётся
  по узлу, а не из модели);
* **APD** = repol − act;
* **удары считаются в каждом узле отдельно** (k-я активация узла — его
  удар k). При блоке проведения в удар k узел «пропускает» удар, и
  дальше номера ударов в разных узлах могут соответствовать разным волнам.

## snapshots/ — снимки полей

`snap_t<время>ms.npz` — все поля в моменты `output.snapshot_times_ms`
(ближайший механический шаг). Значения собраны со всех процессов и
упорядочены по (y, x).

| Ключ | Форма | Смысл |
|------|-------|-------|
| `t_ms`, `requested_ms` | — | момент снимка и заказанные моменты, попавшие в него |
| `e_coords` | (Nₑ, 2) | узлы электрической сетки |
| `e_state` | (Nₑ, n) | все переменные клетки в узлах (столбцы — `e_state_names`) |
| `e_state_names` | (n,) | имена переменных: `V`, `Ca_i`, `Na_i`, `N`, `A`, `l_1`, … |
| `e_region` | (Nₑ,) | регион узла |
| `e_cell_coords`, `e_t_act` | | центры ячеек эл. сетки и переданное клетками T_act, кПа |
| `m_coords` | (Nₘ, 2) | узлы механической сетки в **исходной** (нерастянутой) геометрии |
| `m_u` | (Nₘ, 2) | перемещение узлов от исходной геометрии, мм (включает преднагрузку) |
| `m_cell_coords` | (Cₘ, 2) | центры ячеек механики (исходная геометрия) |
| `m_t_act` | (Cₘ,) | **действующее** активное напряжение, кПа |
| `m_lambda_f` | (Cₘ,) | растяжение волокна |
| `m_J` | (Cₘ,) | det F |
| `m_sigma_xx` | (Cₘ,) | σ_xx, кПа |
| `m_region` | (Cₘ,) | регион ячейки |

Деформированная сетка = `m_coords + m_u`. Карта:
`m_lambda_f.reshape(ny_мех, nx_мех)`, узлы — `(ny_мех+1, nx_мех+1)`.

## XDMF — поля для ParaView

Пишутся каждые `output.save_every_mech_steps` механических шагов.

| Файл | Поля |
|------|------|
| `electrics.xdmf` | каждая переменная клетки под своим именем (`V`, `Ca_i`, …); `T_act_kPa` — переданное клетками T_act |
| `mechanics.xdmf` | `u` — перемещение (вектор); `T_input_kPa` — T_act, пришедшее от клеток; `T_act_kPa` — действующее T_act; `lambda_f`; `J`; `sigma_00` — σ_xx |
| `regions_electric.xdmf`, `regions_mechanical.xdmf` | `region_id`: 0 — база, i — `regions[i-1]` |

Как открыть — [ANALYSIS_GUIDE.md, ParaView](ANALYSIS_GUIDE.md#6-paraview).

## Чекпоинты

| Файл | Когда пишется | Зачем |
|------|--------------|-------|
| `ckpt_preloaded.npz` | сразу после подготовки клеток и преднагрузки | общая стартовая точка для разных протоколов (`--restart … --reset-time`) |
| `ckpt_last.npz` | каждые `output.ckpt_every_mech_steps` шагов и в конце | продолжение, в том числе после аварии |
| `ckpt_t<время>ms.npz` | при `ckpt_keep_all: true` | состояние в каждый момент записи |

Внутри — состояние клеток по узлам электрической сетки и перемещения
механики вместе с **координатами**: продолжать можно на другом числе
процессов. Запись атомарная: если счёт убили во время записи, прежний
`ckpt_last.npz` цел.

## Папка серии

```
runs/my_sweep/
├── sweep.json               сводка серии
├── run_000/ … run_00N/      обычные папки прогонов (см. выше)
├── run_000.log …            вывод каждой точки (при запуске через очередь)
├── run_000.config.json …    конфигурация точки (при запуске через очередь)
├── sweep_table.csv          ← пишет ноутбук 03
└── figures/                 ← пишут ноутбуки 04 и 05
```

`sweep.json`:

| Поле | Смысл |
|------|-------|
| `mode`, `parameters` | режим и изменяемые параметры серии |
| `base` | базовая конфигурация |
| `points[]` | по точке: `name` (`run_000`), `overrides` (значения параметров точки), `label`, `out_dir`, `status`, `error`, `elapsed_s` |
| `started`, `updated` | время |

При запуске через очередь `sweep.json` появляется, когда **все** точки
посчитаны. Состояние: `python -m cardiac_em status runs/my_sweep`.

## Логи

| Файл | Кто пишет | Что внутри |
|------|-----------|-----------|
| `runs/<прогон>.log` | очередь, `nohup … > файл` | сводка конфигурации, ход счёта (t, потенциал, T_act, σ, λ, итерации), итог или ошибка |
| `runs/queue.log` (имя задаёте сами) | очередь | старт / готово / ОШИБКА по заданиям с временем |

Строка хода счёта:

```
     t, мс   u_max     T_эл    T_мех     σ_xx            λ_f  Ньют
     250.0  12.931    58.10    57.95    63.40  1.2410–1.2702     3
```

`u_max` — наибольший потенциал; `T_эл`/`T_мех` — максимум T_act на
электрической/механической сетке; `σ_xx` — максимум напряжения;
`λ_f` — диапазон растяжения волокна; `Ньют` — итерации Ньютона.
