# Инструкция: как запускать расчёты `cardiac_em`

Пошаговое руководство для того, кто работает с кодом впервые: подключиться
к серверу, проверить установку, посчитать первый пример, поставить серию
расчётов в очередь на ночь, проверить результаты и обработать их.

Другие документы:

| Документ | О чём |
|----------|-------|
| [INPUT_FILES.md](INPUT_FILES.md) | входные файлы: конфигурация, протоколы стимуляции, регионы, серии, очередь |
| [OUTPUT_FILES.md](OUTPUT_FILES.md) | что лежит в папке прогона и серии, формат каждого файла |
| [ANALYSIS_GUIDE.md](ANALYSIS_GUIDE.md) | обработка результатов: ноутбуки, Python, ParaView, проверка качества |

## 0. Что считает программа

Двумерный кусок миокарда (например, 8×8 мм), в котором одновременно
решаются две задачи:

* **электрика** — распространение возбуждения (монодоменная модель) с
  ионной моделью кардиомиоцита в каждом узле мелкой сетки. Основная
  модель — **TNNPM** (ten Tusscher–Noble–Noble–Panfilov с механикой
  саркомера), в ней есть АТФ-зависимый калиевый ток — через него
  задаётся **ишемия**;
* **механика** — квазистатическая гиперупругая деформация ткани на
  отдельной, более грубой сетке. Клетки передают в ткань активное
  напряжение, ткань возвращает клеткам длину и скорость укорочения
  волокна (закон сила–скорость).

Один прогон проходит этапы:

```
подготовка клеток   преднагрузка          зажим краёв        стимуляция и счёт
(без стимула,  ──▶  растяжение вдоль ──▶  в растянутом  ──▶  удары по протоколу,
 cell_relax_ms)     волокна до λ_f        положении          запись результатов
                    (preload.stretch)
```

Всё, что задаёт эксперимент (сетки, модель, регионы, протокол стимуляции,
время, вывод), лежит в **одном JSON-файле конфигурации**. Код менять не
нужно.

## 1. Что понадобится

* учётная запись на расчётном сервере (логин и адрес — у руководителя);
* **VS Code** с расширениями *Remote - SSH*, *Python*, *Jupyter*;
* минимум команд Linux:

| Команда | Что делает |
|---------|-----------|
| `cd папка` | перейти в папку (`cd ~/cardio2d` — в проект) |
| `ls`, `ls -lh папка` | список файлов (с размерами) |
| `cat файл`, `tail -n 20 файл`, `tail -f файл` | показать файл / конец / следить за ростом (выход — Ctrl+C) |
| `nproc`, `htop` | сколько ядер; кто их занимает (выход — `q`) |
| `df -h .`, `du -sh runs/*` | свободное место; сколько занимают прогоны |
| `kill PID`, `pkill -f шаблон` | остановить процесс по номеру / по части командной строки |

## 2. Шаг 1 — подключиться к серверу

В терминале:

```bash
ssh <логин>@<сервер>
```

В VS Code: `Ctrl+Shift+P` → **Remote-SSH: Connect to Host…** → ввести
`<логин>@<сервер>` → **File → Open Folder** → `~/cardio2d`.

Всё дальнейшее делается в терминале VS Code (**Terminal → New Terminal**)
на сервере — в нижней панели должно быть видно `<логин>@<сервер>`.

## 3. Шаг 2 — окружение (один раз)

Код работает в окружении conda `fenicsx-env` (в нём DOLFINx, MPI, PETSc).
**Его нужно активировать в каждом новом терминале:**

```bash
conda activate fenicsx-env
cd ~/cardio2d
```

Приглашение станет `(fenicsx-env) …$`. Проверка:

```bash
python -c "import dolfinx, cardiac_em; print(dolfinx.__version__, cardiac_em.__version__)"
which mpirun
```

Если `cardiac_em` не импортируется — установить пакет в режиме
разработки (один раз):

```bash
pip install -e ".[notebooks]"
```

Ядро для ноутбуков (один раз):

```bash
python -m ipykernel install --user --name fenicsx-env --display-name "Python 3 (fenicsx-env)"
```

В ноутбуке VS Code: **Select Kernel** (справа вверху) → *Jupyter Kernel…*
→ **Python 3 (fenicsx-env)**.

## 5. Шаг 4 — первый расчёт

Самый простой путь — ноутбук **`notebooks/01_run.ipynb`** → **Run All**.
Он берёт пример `examples/tnnpm_ischemia.json`, уменьшает его (сетка
30×30 на 3×3 мм, 450 мс), считает ~4 минуты и пишет результат в
`runs/nb_quick/`. Затем откройте `03_analysis.ipynb`, `04_visualization.ipynb`
и `05_deformation.ipynb` и выполните их — это и есть весь цикл «посчитал →
посмотрел».

Тот же расчёт из терминала:

```bash
# 1) посмотреть, что будет посчитано (DOLFINx не нужен, мгновенно)
python -m cardiac_em show examples/tnnpm_ischemia.json --t-end 450 --out runs/first

# 2) посчитать на одном ядре
python -m cardiac_em run examples/tnnpm_ischemia.json --t-end 450 --out runs/first

# 3) состояние
python -m cardiac_em status runs/first
```

`show` печатает сводку (сетки, модель, стимулы, время) и
**предупреждения** `[!]` — читайте их: стимул позже конца счёта, снимки
вне интервала, слишком грубая механическая сетка и т.п.

## 6. Шаг 5 — своя конфигурация

**Никогда не правьте файлы в `examples/` на месте** — скопируйте:

```bash
mkdir -p configs
cp examples/tnnpm_ischemia.json configs/my_first.json
```

Откройте `configs/my_first.json` в VS Code и поменяйте нужное. Все поля
описаны в [INPUT_FILES.md](INPUT_FILES.md); самые частые:

| Что | Где в JSON |
|-----|-----------|
| размер области и сетки | `mesh.electric.{nx, ny, lx_mm, ly_mm}`, `mesh.mechanical.{…}` |
| моменты стимулов | `stimulus.times_ms` |
| длительность счёта | `time.t_end_ms` |
| ишемическая зона | `regions[…]` (форма, размер, `cell:K_o`, `cell:ATP_i`, `cell:KmATP`) |
| преднагрузка | `preload.stretch`, `preload.cell_relax_ms` |
| куда писать | `output.out_dir` |
| снимки полей | `output.snapshot_times_ms` |

Параметр можно поменять и **без правки файла** — флагом `--set`
(путь через точку, значение в JSON):

```bash
python -m cardiac_em show configs/my_first.json \
    --set time.t_end_ms=3000 \
    --set "stimulus.times_ms=[1,1001,2001]" \
    --set regions.0.overrides.cell:K_o=8.0
```

Всегда сначала `show` — опечатка в пути или недопустимое значение
сразу даст понятную ошибку, а не упадёт через час счёта.

## 7. Шаг 6 — параллельный счёт и счёт в фоне

### Параллельно (MPI)

```bash
mpirun -n 8 python -m cardiac_em run configs/my_first.json --out runs/my_first
```

`-n 8` — число процессов (ядер). Результат от числа процессов
практически не зависит (различия — на уровне ошибок округления). Разумно 1 процесс на 2–4 тысячи узлов электрической сетки.

### В фоне — чтобы счёт не остановился при закрытии VS Code

```bash
nohup mpirun -n 8 python -m cardiac_em run configs/my_first.json \
    --out runs/my_first --every 100 > runs/my_first.log 2>&1 &
```

* `nohup … &` — процесс живёт после отключения от сервера;
* `> runs/my_first.log 2>&1` — весь вывод в файл;
* `--every 100` — строка хода счёта каждые 100 мс модели.

Следить:

```bash
tail -f runs/my_first.log                 # ход счёта (Ctrl+C — выйти из просмотра, счёт идёт)
python -m cardiac_em status runs/my_first # running, t = … из … мс
htop                                      # загрузка ядер
```

Остановить:

```bash
pkill -f "runs/my_first"                  # все процессы этого прогона
```

Прерванный прогон получает `status = running` (или `failed`); его можно
**продолжить с последнего чекпоинта** (шаг 9).

### Сколько ядер брать

Сервер общий. Перед запуском посмотрите `htop` — сколько ядер уже
занято. Правило: **(ранги на задание) × (заданий одновременно) ≤ число
ядер − 4**. На 32-ядерном сервере, например, 3 задания по 8 рангов.

## 8. Шаг 7 — серия расчётов

Серия — базовая конфигурация и список изменяемых параметров. Файл серии
(например, `configs/sweep_stages.json`):

```json
{
  "base": "my_first.json",
  "out_root": "runs/stages",
  "mode": "zip",
  "parameters": {
    "regions.0.overrides.cell:K_o":   [9.4, 8.0, 5.4],
    "regions.0.overrides.cell:ATP_i": [4.0, 4.5, 6.8],
    "regions.0.overrides.cell:KmATP": [0.38, 0.35, 0.09]
  }
}
```

* `base` — путь к конфигурации **относительно файла серии**;
* `mode: "zip"` — i-е значения берутся вместе (3 прогона: стадии);
  `mode: "grid"` — все сочетания (3 × 3 × 3 = 27 прогонов);
* каждая точка пишется в `out_root/run_000`, `run_001`, …

Проверить без счёта:

```bash
python -m cardiac_em sweep configs/sweep_stages.json --dry-run
```

Серию можно запустить командой `cardiac_em sweep` (точки идут **по
очереди**, каждая под `mpirun`), но удобнее — через очередь (шаг 8):
она считает несколько точек **одновременно** и позволяет добавлять
задания на ходу.

## 9. Шаг 8 — очередь расчётов (основной способ запуска)

Очередь — текстовый файл со списком заданий. Скрипт `scripts/queue.py`
берёт задания сверху вниз и держит запущенными заданное число
одновременно.

### 9.1. Файл очереди

Например, `configs/queue.txt` (образец — `examples/queue_example.txt`):

```text
# серия — путь к JSON серии
configs/sweep_stages.json

# одиночный прогон — конфигурация и флаги, как у `cardiac_em run`
configs/my_first.json --out runs/long_3s --t-end 3000 --set stimulus.times_ms=[1,1001,2001]
```

Пути — от корня проекта. `#` — комментарий.

### 9.2. Проверить и запустить

```bash
python scripts/queue.py configs/queue.txt --dry-run            # что будет запущено
nohup python scripts/queue.py configs/queue.txt --np 8 --parallel 3 \
    > runs/queue.log 2>&1 &
```

* `--np 8` — рангов MPI на одно задание;
* `--parallel 3` — сколько заданий одновременно (итого 24 ядра);
* каждая точка серии и каждый прогон — отдельное задание; вывод
  задания — в `<папка прогона>.log` (например, `runs/stages/run_000.log`);
* когда все точки серии готовы, автоматически пишется её сводка
  `runs/stages/sweep.json` (её читают ноутбуки анализа).

### 9.3. Следить

```bash
tail -f runs/queue.log                             # старт/готово/ошибка по заданиям
python scripts/queue.py configs/queue.txt --status # таблица: finished / running (t, %) / ждёт
tail -n 3 runs/stages/run_000.log                  # ход одного задания
```

### 9.4. Добавить задание, пока очередь работает

Просто допишите строку в `configs/queue.txt` и сохраните. Очередь
перечитывает файл, когда освобождается место.

### 9.5. Остановить

```bash
touch configs/queue.txt.stop     # новые задания не начнутся, текущие досчитаются
rm configs/queue.txt.stop        # снять запрет перед следующим запуском
```

Немедленно (прервав счёт): `pkill -f queue.py; pkill -f "cardiac_em run"`.

### 9.6. Перезапуск

Очередь **пропускает готовые прогоны** (`status = finished` в их
`run.json`). Если ночью что-то упало или очередь остановили — запустите
её снова той же командой: досчитается только недостающее. Упавшее
задание сначала посмотрите в его `.log`.

`--watch` — не завершаться, когда задания кончились, а ждать новых
строк (удобно держать очередь открытой на несколько дней; остановка —
файлом `.stop`).

## 10. Шаг 9 — продолжить или удлинить расчёт

Каждый прогон сохраняет чекпоинты:

* `ckpt_preloaded.npz` — сразу после подготовки клеток и преднагрузки;
* `ckpt_last.npz` — последнее состояние (по умолчанию каждые 100 мс).

Продолжение — **новый прогон в новой папке**:

```bash
python -m cardiac_em run configs/my_first.json --out runs/my_first_cont \
    --restart runs/my_first/ckpt_last.npz --t-end 5000 \
    --set "stimulus.times_ms=[3001,4001]"
```

* `--t-end` — **абсолютное** время конца (если чекпоинт на 3000 мс,
  нужно больше 3000);
* моменты стимулов — тоже абсолютные;
* преднагрузка и подготовка клеток при продолжении не повторяются.

Разные протоколы из одного подготовленного состояния: берите
`--restart runs/<прогон>/ckpt_preloaded.npz` и добавьте `--reset-time`,
чтобы время снова шло от нуля. Подробнее — в
[INPUT_FILES.md](INPUT_FILES.md#8-продолжение--restart).

## 11. Шаг 10 — обработать результаты

Коротко (подробно — [ANALYSIS_GUIDE.md](ANALYSIS_GUIDE.md)):

1. `python -m cardiac_em status runs/<прогон или серия>` — всё `finished`?
2. Ноутбуки, в каждом поменять путь в первой ячейке с параметрами:

| Ноутбук | Переменные | Что получите |
|---------|-----------|--------------|
| `03_analysis.ipynb` | `RUN_DIR`, `SWEEP_DIR` | таблицы: удары, CV, APD по регионам, блок, реституция, серия; CSV в `runs/<прогон>/analysis/` |
| `04_visualization.ipynb` | `RUN_DIR`, `SWEEP_DIR`, `BEAT`, `SNAP_T_RANGE` | ряды, карты активации/APD/CV, снимки, механика, анимация; PNG в `runs/<прогон>/figures/` |
| `05_deformation.ipynb` | `RUN_DIR`, `SWEEP_DIR`, `AMPLIFY` | деформация: исходная сетка → преднагрузка → пик удара, раскадровка, стационар, стадии |

3. Полные поля во времени — `electrics.xdmf` / `mechanics.xdmf` в
   ParaView.

## 12. Сколько это считается и сколько занимает

Замеры на 32-ядерном сервере лаборатории (TNNPM, dt = 0.05 мс):

| Задача | Узлов эл. сетки | Время модели | Ранги | Время счёта |
|--------|-----------------|--------------|-------|-------------|
| быстрый пример (01_run) | 31×31 | 100 мс + 100 мс подготовки | 1 | ~50 с |
| 8×8 мм, h = 0.05 мм, 3 точки одновременно | 161×161 | 2000 мс + 300 мс | 8 на точку | ~70 мин |
| то же, 10 ударов 1 Гц | 161×161 | 10 000 мс + 300 мс | 8 на точку | ~5.5 ч |

Грубо: время ∝ (число узлов) × (время модели) / (ранги). Удвоение
разрешения сетки по каждой оси — в 4 раза больше узлов.

Диск: ~1 ГБ на прогон 8×8 мм / 10 с при записи полей раз в 50 мс; больше
всего занимают `*.h5` (поля для ParaView). Проверяйте `df -h .` перед
большой серией.

## 13. Правила работы

1. **Код в `cardiac_em/` не меняем** без согласования. Всё, что меняется
   от эксперимента к эксперименту, — в конфигурации.
2. Свои конфигурации, серии и очереди — в `configs/` (не в `examples/`).
3. Одно исследование — одна папка в `runs/` с говорящим именем:
   `runs/ischemia_size_r1-3mm`, а не `runs/test2`.
4. Перед запуском: `show` (или `sweep --dry-run`, или
   `queue.py --dry-run`) и `htop`.
5. Журнал экспериментов (таблица или текстовый файл): дата, папка,
   файл конфигурации, цель, что получилось. Полная конфигурация
   каждого прогона всё равно сохраняется в его `run.json`.
6. Большие `*.h5` удаляйте, когда поля уже не нужны: анализ идёт по
   `series.csv`, `activation.npz` и снимкам.
7. Сервер общий: не берите все ядра; большие серии — на ночь через очередь.

## 14. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| `ModuleNotFoundError: dolfinx` | не активировано окружение / не то ядро | `conda activate fenicsx-env`; в ноутбуке — ядро «Python 3 (fenicsx-env)» |
| `ModuleNotFoundError: cardiac_em` | пакет не установлен или запуск не из корня | `cd ~/cardio2d; pip install -e ".[notebooks]"` |
| `mpirun: command not found` | не то окружение | `conda activate fenicsx-env` |
| `ошибка: … уже есть run.json` | папка вывода занята | другое `--out` или `--overwrite` (старый результат будет перезаписан!) |
| `ошибка: --set: …` | опечатка в пути параметра | сверить путь с JSON (`show --json` показывает всю конфигурацию) |
| `[!] стимулы … позже конца счёта` | `t_end_ms` меньше моментов стимулов | увеличить `time.t_end_ms` или убрать лишние стимулы |
| счёт остановился после закрытия VS Code | запуск без `nohup` | запускать через `nohup … &` или очередь |
| `status: failed`, в логе «механика не сошлась: SNES reason=…» (или `NaN`) | слишком большой шаг нагружения, вырожденная деформация | при преднагрузке — увеличить `preload.n_steps`; при счёте — уменьшить `time.n_electric_per_mech` (чаще механика); в сообщении указан момент `t` сбоя; прислать руководителю лог |
| волна не пошла (`u_max` не растёт) | слабый или узкий стимул | `stimulus.amplitude` ↑, `x_max_mm` ≥ 2 ячеек сетки; `show` предупреждает |
| прогон очень медленный | ядра заняты другими | `htop`; уменьшить `--np`/`--parallel` или ждать |
| `No space left on device` | диск заполнен | удалить ненужные `*.h5`, старые прогоны; `du -sh runs/*` |
| очередь «ничего не делает» | все задания готовы или есть файл `.stop` | `queue.py … --status`; удалить `.stop` |

Если непонятно — пришлите руководителю: команду запуска, последние
30 строк лога (`tail -n 30 …log`) и `python -m cardiac_em status <папка>`.

## 15. Шпаргалка

```bash
conda activate fenicsx-env && cd ~/cardio2d        # начало каждой сессии

python -m cardiac_em show  CFG.json [--set путь=значение …]      # проверить конфигурацию
python -m cardiac_em run   CFG.json --out runs/X                   # посчитать (1 ядро)
```
